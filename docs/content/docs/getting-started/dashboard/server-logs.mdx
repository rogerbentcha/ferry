Click **Server** in the icon rail. Then click **Server logs**. The section shows the <Term id="server-log" />: the last 2,000 lines, then each new line live. It is the same with `ferryd start` and with `ferryd run`.

## The tools

| Tool | Use |
|---|---|
| Level | Show the lines of one level and of the more important levels: **Error**, **Warn**, **Info** or **Debug**. **Warn** shows the warnings and the errors. |
| Search | Show only the lines that contain the text. |
| Copy | Copy one line. Move the pointer onto the line to see the button. |
| Wrap | Wrap the long lines. |
| Timestamps | Show or hide the time of each line. |
| Reconnect, Clear | Open the stream again. Remove the lines from the page. |

## The colors

| Level | Color |
|---|---|
| `ERROR` | Red, with a red mark in the margin |
| `WARN` | Orange, with an orange mark in the margin |
| `INFO` | Blue |
| `DEBUG` | Gray |

## Read old lines

Scroll up. The auto-scroll stops. Click **Jump to latest** to start it again.

<Accordions>
  <Accordion title="Lines skipped">
    If the page is slower than the server, the server does not wait for it. The page loses lines, and a line such as `1,500 lines skipped` shows where. The output of ferryd keeps all the lines.
  </Accordion>
  <Accordion title="No debug lines">
    By default, ferryd writes the `info` level and the levels above it. To see the `debug` lines, start ferryd with `RUST_LOG=debug`. The section shows the `debug` lines of Ferry. The `debug` lines of the libraries that Ferry uses stay in the output of ferryd.
  </Accordion>
  <Accordion title="API">
    The section reads `GET /api/v1/server/logs`. See [Server metrics and logs](/docs/reference/api/server) and [Stream logs with the API](/docs/concepts/logs/api-streams).
  </Accordion>
</Accordions>
