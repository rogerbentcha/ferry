---
title: The metrics
description: The list of the numbers that Ferry publishes at /metrics, with their type and their labels.
---

```text title="GET /metrics" noCopy
ferry_host_memory_available_bytes 5368709120
ferry_container_cpu_percent{kind="service",id="srv-…",name="web",instance_id="9f8e7d"} 120.5
ferry_http_requests_total{target="srv-…",name="web",status_class="5xx"} 10
```

All the names start with `ferry_`. A value is in bytes, seconds or percent. A <Term id="counter" /> only goes up and its name ends with `_total`.

## The list

| Metric | Labels | Content |
|---|---|---|
| `ferry_build_info` | `version` | Always 1 |
| `ferry_host_cpu_count` | | The CPUs of the machine |
| `ferry_host_cpu_seconds_total` | `mode` | The seconds of all the CPUs in each mode of `/proc/stat`: `user`, `system`, `idle`, `iowait`… |
| `ferry_host_memory_total_bytes` | | The memory of the machine |
| `ferry_host_memory_available_bytes` | | The memory that is not in use |
| `ferry_host_disk_total_bytes`, `ferry_host_disk_used_bytes` | `mount_point` | The size and the used space of each disk of the Monitoring page |
| `ferry_host_disk_read_bytes_total`, `ferry_host_disk_written_bytes_total` | `mount_point` | The bytes read and written |
| `ferry_host_network_receive_bytes_total`, `ferry_host_network_transmit_bytes_total` | `device` | The bytes received and sent by each interface, without the loopback and Docker |
| `ferry_container_cpu_percent` | `kind`, `id`, `name`, `instance_id` | The CPU of each instance and datastore. 100 is one core. |
| `ferry_container_memory_bytes` | `kind`, `id`, `name`, `instance_id` | The memory, without the page cache |
| `ferry_http_requests_total` | `target`, `name`, `status_class` | The requests, by class: `2xx` to `5xx` |
| `ferry_http_request_duration_seconds` | `target`, `name` | A <Term id="histogram" /> of the <Term id="latency" /> |

## The labels

| Label | Value |
|---|---|
| `device` | A network interface, for example `eth0` |
| `kind` | `service` or `datastore` |
| `id`, `name` | The ID and the name of the service or the datastore |
| `instance_id` | The instance, as in the logs. A datastore has none. |
| `target` | The ID of a service, `dashboard`, or `unrouted` |

<Accordions>
  <Accordion title="A value that is not there">
    If ferryd cannot read a value, the metric is not in the answer: it is never 0. On a Mac, ferryd publishes only the CPU count and the space of the disks. If Docker does not answer, the metrics of the containers are not there.
  </Accordion>
  <Accordion title="When ferryd restarts">
    The counts of the requests start again from 0. Prometheus sees the reset: `rate()` and `increase()` stay correct. The counters of the machine count from the start of the machine. The counters of a network interface count from the start of the interface.
  </Accordion>
  <Accordion title="Why instance_id and not instance">
    Prometheus gives the label `instance` to each number that it collects: the address of the target. A label `instance` from Ferry would become `exported_instance`.
  </Accordion>
  <Accordion title="What the proxy counts">
    The rules are the same as for the [Requests charts](/docs/getting-started/dashboard/server-requests). The histogram stops when the headers of the answer go out. A <Term id="websocket" /> counts as a 2xx, and is not in the histogram.
  </Accordion>
</Accordions>
