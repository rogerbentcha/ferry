The first four steps come before the first <Term id="reconciler-pass" />.

## Builds that a killed server left running

A server that stops normally stops its builds. A server that gets <Term id="sigkill" /> cannot stop them. On macOS, a `docker build` then continues without the server.

While a build runs, Ferry records each `git` and `docker` process of the build in the scratch directory of the build. At the next start, the engine stops these processes. Then it deletes the scratch directories. If a different program now has the process number of a record, the engine does not stop it.

## Deploys that were not complete

| Status at the stop | New status |
|---|---|
| `queued` or `building` | `build_failed` |
| `deploying` | `deploy_failed` |

The error is `interrupted by server restart`. The job runs with the status pending or `running` get the same error.

The containers of these deploys never got traffic. The first pass removes them immediately.

See also [Server shutdown and restart](/docs/architecture/deploy-pipeline/shutdown).
