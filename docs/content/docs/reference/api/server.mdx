          use (0–100 % of the whole machine) and CPU count, memory used without
          the page cache and total, the used and total space and the read /
          write speed of the disk of the data directory (and of Docker's data
          directory when it is another local disk), and the network traffic

          every running service instance and datastore with its CPU use (100 =
          one core), memory use and limits, the busiest first. Speeds are bytes
          per second since the previous call (within a minute) or over one
          second, so a call takes about a second. Every call reads again: the
          last 24 hours are `GET /api/v1/server/metrics/history`. A value the
          server can't read is `null` (on macOS, most host values); `containers`

          container that does not answer in time are `null`."

          reads the server every 10 s while it runs and keeps 24 hours of
          readings in its database. They come back averaged into steps
          (`step_seconds`: 10, 60 or 240), 360 points at most per series, oldest
          first, each at the start of its step. A step without a reading —
          ferryd was stopped — has no point, so a gap between two points is a
          time without data. The host: CPU use (0–100 % of the machine), memory
          used and total, the read / write speed of its disks together and the
          network traffic, like `GET /api/v1/server/metrics`. The containers:
          the 5 service instances and datastores whose CPU use (100 = one core)

          value that could not be read in a whole step is `null`."
